Updating raw data

This page describes what to do when a source publishes a new data vintage. The general procedure is the same for every file:

  1. Download the new file from the source listed in Raw data sources and place it in data/raw/ (or the subfolder named below), keeping the old file until the new run is validated.
  2. Edit the constant at the top of the consuming script that names the file, quoted below for each file.
  3. Check the structural assumptions listed for that file. The scripts read sheets, header rows and columns by name or position; a new vintage that changes them fails loudly (a missing sheet or column) or, worse, silently (a shifted column read by position).
  4. Rerun the pipeline (scripts/run_r_pipeline_unix.sh, the .bat twin, or Rscript main.R from code/processing/; see Processing pipeline) and go through the checklist at the end of this page.

Files are grouped by source. “Consumed by” names the scripts in code/processing/R/. Year constants that must move together with the vintage are collected in “Moving the analysis period”.

USDA baseline

2025 International Long-Term Projections to 2034.xlsx

  • Consumed by: 10_read_baseline_data.R.
  • Constant: baseline_data <- "2025 International Long-Term Projections to 2034.xlsx".
  • To update: drop the new workbook in data/raw/, edit baseline_data, update region_commodity_list_2025.xlsx if the set of regions per commodity changed, rerun.
  • Assumptions: one sheet per commodity named exactly Barley, Beef and veal, Corn, Cotton, Pork, Poultry, Rice, Sorghum, Soybeans, Soybean meal, Soybean oil, Wheat. Within a sheet, region tables appear in the order of the region list followed by World, each 25 rows apart; the first data block spans rows 9 to 29 for Poultry and rows 7 to 27 for every other commodity, and holds 6 (Poultry, Beef and veal, Pork), 8 (Rice), 9 (Cotton), 10 (Barley, Corn, Sorghum, Wheat, Soybean meal, Soybean oil) or 11 (Soybeans) columns whose meaning is fixed in the script. Missing values are the string --; the year column holds crop years such as 2025/26. Any change in the row spacing, the starting row, the column set of a commodity group, or the region order breaks the read silently (values land under the wrong name), so compare data/interim/baseline_projections_long.csv against the workbook for a few regions after the first run.

region_commodity_list_2025.xlsx

  • Consumed by: 01_check_region_commodity_coverage.R, 10_read_baseline_data.R.
  • Constant: input_path_list <- file.path(base_dir, "raw", "region_commodity_list_2025.xlsx") in both scripts.
  • To update: project-maintained. Rebuild it from the new workbook’s table of contents (one row per region and commodity, in the order the regions appear in each commodity sheet), edit the two constants, rerun.
  • Assumptions: sheet Sheet1 with columns region and commodity; region names must match those in mapping.csv (column region) and commodity names must match the sheet names of the baseline workbook.

baseline_units.csv

  • Consumed by: 12_generate_data_targets.R (declared but not read by 24_generate_data_exogenous.R).
  • Constant: input_path_units <- file.path(base_dir, "raw", "baseline_units.csv").
  • To update: project-maintained; edit in place only if the baseline changes units (for example cotton bales).
  • Assumptions: columns commodity, commodity_name, attribute_description, unit, joined on commodity (model code) and attribute_description.

Prices and CPI

2026-06-19 IMF Commodity Prices external-data.xlsx

  • Consumed by: 20_compute_ag_expenditure_share.R.
  • Constant: input_path_imf <- file.path(base_dir, "raw", "2026-06-19 IMF Commodity Prices external-data.xlsx").
  • To update: download the IMF Primary Commodity Prices monthly workbook, drop it in data/raw/, edit the constant, rerun.
  • Assumptions: sheet External, read without headers. Row 1 holds the commodity codes; the script selects PBARL, PWHEAMT, PCOTTIND, PRICENPQ, PMAIZMT, PSORG, PSOYB, PSMEA, PSOIL (table imf_meta, which also fixes each commodity’s marketing-year start month). Column 1 holds date labels YYYYMm (for example 2025M3); other rows are ignored. Units must stay USD per metric ton, except cotton and sorghum in US cents per pound, because the conversion in 20 and 24 is hard-coded per commodity.

2026-06-19 International Prices FAO Meat.xlsx

  • Consumed by: 20_compute_ag_expenditure_share.R.
  • Constant: input_path_fao <- file.path(base_dir, "raw", "2026-06-19 International Prices FAO Meat.xlsx").
  • To update: export the same ten export-price series from the FAO GIEWS FPMA international prices tool, in the same column order, drop the file in data/raw/, edit the constant, rerun.
  • Assumptions: sheet data, read without headers; column 2 holds dates MM/DD/YYYY; the meat averages use fixed column positions (columns 3, 4, 5 for beef: United States, Australia, Brazil; 6, 8, 9 for pork: Brazil, EU, United States; 7 and 10 for poultry: Brazil, United States), so adding, removing or reordering a series in the export changes the averages silently. Prices are USD per tonne.

2026-06-24 CPI_US.xlsx

  • Consumed by: 20_compute_ag_expenditure_share.R.
  • Constant: input_path_cpi_17 <- file.path(base_dir, "raw", "2026-06-24 CPI_US.xlsx").
  • To update: extend the annual-average CPI-U series (BLS or FRED CPIAUCNS) in the workbook, recompute CPI_2017 as the annual average divided by the 2017 average, edit the constant, rerun.
  • Assumptions: sheet Sheet1 with columns year, AVG_CPI, CPI_2017; joined on year, and every year with price data must be present (a missing year yields missing deflated prices). The base year 2017 is fixed by the price units of the model (USD Million (prices of 2017)).

Trade barriers

All files live in data/raw/trade_barriers/. Five of them are not distributed with the repository (two for size, three because of UNCTAD TRAINS and WTO terms): tariff_ave_WITS_2023.csv, tariff_ave_2014_WITS.csv, ag_hs_products.csv, ag_tariff_USA_2014.xls and BACI_HS92_Y2014_V202401b.csv. Their derived products are shipped in data/interim/ and reused by main.R when the raw files are absent. A refresh of any of them requires obtaining the file from its source (query settings in Raw data sources; scripts/fetch_large_raw_data.sh reports which are present and downloads the CEPII file), then rerunning scripts 22 and 23, which rewrite the derived files.

tariff_ave_WITS_2023.csv (not distributed)

  • Consumed by: 22_compute_tariff_ave.R; its presence is also tested by main.R, which otherwise reuses the shipped data/interim/tariff_ave_region.csv and export_taxes_comm_reg.csv.
  • Constant: input_path_tariff <- file.path(base_dir, "raw", "trade_barriers/tariff_ave_WITS_2023.csv"), and the file name in main.R (tariff_raw) and in the fetch scripts.
  • To update: obtain the file from WITS (Advanced Query, TRAINS, all reporters, all partners, all HS6 products, the new year, AVE of applied tariff, CSV export), drop it in the folder, edit the constant, and edit the string year = "2023 (or last observed)" written to the output; rerun. Script 22 then rewrites the two derived files in data/interim/, which are tracked in git.
  • Assumptions: WITS export columns Reporter (numeric code), Product (HS code, leading zero dropped), DutyType, Simple Average, Tariff Year (read as Simple.Average, Tariff.Year). Only DutyType == "MFN" rows are used. Product codes of 3 or 5 digits get a leading zero; the commodity mapping uses fixed HS4 and HS6 lists, so a nomenclature revision that moves the modeled products to other headings requires editing that mapping. The EU must be reported as one reporter (EUN in country_code_WITS.xlsx).

Moving the analysis period

When the USDA baseline advances a year, the following year constants must move together (all in code/processing/R/):

  • 12_generate_data_targets.R: lst_obsv_yr <- 2025.
  • 30_generate_data_shocks.R: first_yr <- 2025, last_yr <- 2034.
  • 11_compute_feed_use_decomposition.R: filter(year >= 2025).
  • 20_compute_ag_expenditure_share.R: years <- 2025:2034, the GDP level and growth columns (see the GDP shares file above), filter(year == 2025) for the expenditure and the exported share.
  • 21_compute_land_cost_share.R: filter(year >= 2024 ...) and filter(year>=2025).
  • 24_generate_data_exogenous.R: marketing_year == 2025 for prices, year == 2025 for population and GDP, Year = 2024 and year = 2024 for livestock.
  • The model run: scripts/run_model_unix.sh and .bat default to 2025:2034, and code/model/test/runtests.jl pins the same period for the baseline package.

The package name written by 60_build_input_package.R follows the first year of data_targets.csv automatically.

Checklist for a full refresh

  1. Place the new raw files in data/raw/ and edit the file name constants and year constants listed above. Keep the previous data/processed/ and data/packages/ copies for comparison (they are tracked in git, so git diff and git stash work).
  2. Decide whether scripts 22 and 23 run or are skipped. They run only when their raw inputs that are not distributed are under data/raw/trade_barriers/ (scripts/fetch_large_raw_data.sh reports which of the five are present); otherwise main.R reuses the derived files shipped in data/interim/. A refresh of the trade-barrier sources requires the raw files, and the rerun rewrites the tracked derived files.
  3. Run the pipeline: scripts/run_r_pipeline_unix.sh or scripts\run_r_pipeline_windows.bat (or Rscript main.R from code/processing/). It must end with main.R ... ALL DONE. Read the console for the 50_harmonize_targets: summary line and any warning about unmatched names.
  4. Inspect data/interim/harmonization_log.csv. Expect rows with delta 1 or 2 and status adjusted, on both checks; a status containing outside or a residual larger than 2 points to a broken read in script 10 or a changed baseline layout.
  5. Spot-check the intermediates against the sources: baseline_projections_long.csv for two or three regions, variable_costs_us_2025.csv for all seven crops, international_prices_annual.csv for the last marketing year, and ag_expenditure_shares.csv for plausible shares.
  6. Diff the new data/processed/*.csv against the previous vintage (row counts per attribute, new or missing region-commodity pairs) before accepting them.
  7. Run the model on the new package: scripts/run_model_unix.sh data/packages/baseline_<year>_Input.zip output/baseline_Output.zip <first>:<last> (or the .bat twin). Every year should report a solved status in the solver log.
  8. Check that the neutral run reproduces the new targets: upload the output package to the dashboard (Dashboard). With neutral shocks every ratio of solution to baseline is 1, so “Top # Regional Changes” shows zero percent change for every attribute and year. A nonzero change in yields or extraction rates points at script 50 (derived series); a nonzero change elsewhere points at the harmonization log.
  9. Once validated, refresh the regression reference: code/model/test/expected/baseline_<year>_Input.sha256 and the fixture path in code/model/test/runtests.jl, then julia --project=code/model code/model/test/runtests.jl.
  10. Update Raw data sources (file names and vintage dates), this page, and Processing pipeline if any script header changed.
